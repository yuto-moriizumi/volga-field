## 発見した問題

### 1. 【重大】クライアントとサーバーの状態不整合

対象: `apps/web/src/app/room/[roomId]/GameRoom.tsx`

`GameRoom` が `lastMessage` のみを監視してローカルの `gameState` を更新している。
サーバーは `game_state` の直後に `card_played` を送信するため、
React のバッチ処理で間の `game_state` が捨てられ、画面が古い状態のまま残る。

再現手順:

1. 修行モードで回復薬を使用する
2. サーバー側では成功（HP 12→17、ログに「5回復」、手札から消費）
3. 画面は HP 12 のまま、回復薬も手札に残る
4. 同じカードを使おうとすると `card not in hand` エラー
5. ターン終了で次の `game_state` が届いた瞬間に HP 17・手札5枚へ修正される

関連箇所:

- `GameRoom.tsx` の `lastMessage` 監視による `setGameState`
- `apps/server/src/index.ts` の `handlePlayCard` 内 `broadcastStateToAll` → `card_played` 送信

修正方針:

`GameRoom` のローカル状態を `lastMessage` ではなく、
`GameContext` が毎回更新している `ctxGameState` に同期させる。

### 2. 回復が最大HPを超える — 意図した仕様（バグではない）

対象: `packages/game-core/src/player.ts` の `healPlayer`

`healPlayer` に `maxHp` の上限処理はないが、これは意図した仕様とする。
**HPには上限がなく、回復によって20を超えてよい。** HP20で回復薬を使うと HP25/20 になるのは正常。

`recoverMp` が `maxMp` で上限処理しているのはMP側の仕様であり、HP側の漏れではない。
HPに上限を追加する修正は行わない。

### 3. 山札の切り出し方法により、連続プレイでほぼ同じ内容になる

対象: `packages/game-core/src/deck.ts` の `buildDeck`

`Date.now()` を開始位置にして連続した30枚を切り出している。

- 仕様は「全99枚の中から30枚を選んでデッキを作る」
- 現状の実装は開始位置が時刻依存のため、数秒後に開始した次のゲームは29/30枚が同じになる
- 新しく追加したカードがそのゲームに一切出ないことがある
- `packages/game-core/src/cards.ts` の `DECK_SIZE` は未使用

修正方針: 全カードから30枚を選ぶ（シャッフルして先頭30枚を採用するなど）。
デッキ生成の改修は別エージェントが担当する。

### 4. 修行モードと対人戦でターンルールが異なる — 複数枚プレイに統一する

対象: `apps/server/src/index.ts` の `handlePlayCard`

相手がAIのときだけ、防御解決後にこちらのターンを自動終了している。
対人戦では攻撃後も続けてカードを出せるため、モードによって挙動が変わる。

決定: README のルールどおり、**1ターン中に複数のカードをプレイしてからターン終了できる**ことを正とする。
修行モード側をこのルールに統一する（修行モードのみ自動終了している現状を改める）。
修行テンポのための例外的な自動終了は行わない。

### 5. リロード・再接続でゲームに戻れない（今回は保留）

対象: `apps/server/src/index.ts` の `handleJoinRoom`

開始済みルームへの参加は「ゲームは既に開始しています」で拒否される。
WebSocket はクライアント内の画面遷移では維持されるが、
ブラウザ更新や再接続で新しいクライアントIDになると復帰できない。

再接続用トークンや、既存プレイヤーIDへの再紐付けが未実装。
今回は対応せず、後続のウェーブで扱う。

### 6. 教典と実装の乖離が大きい

対象: `apps/web/src/app/textbook/data.ts`

教典には以下の仕様が記載されているが、`packages/game-core` に実装がない。

- 属性（社会主義 / 資本主義 / 共和主義 / 封建主義 / 環境主義 / 無政府主義）の防御相性
  - エンジンのカード定義に `attribute` フィールド自体が存在しない
- 災い（風邪、熱病、地獄病、天国病、霧、閃光、夢、暗雲）
- 超常現象（日蝕、流星群、次元断裂）
- 一部の武器・防具・雑貨（こん棒、短剣、小盾、薬草、解毒草、爆弾など）

これらは構想段階のコンテンツであり、今回は削除しない。
教典ページ冒頭に「構想・未実装の内容を含む。実装済みカードの正は
`packages/game-core/src/cards.ts`」という注意書きを掲示して区別する。

実装済みだが教典に載っていなかった以下のカテゴリ・カードは、今回の同期で追記した。

- 無属性の外交カード（懸念を表明する 〜 最も強い言葉で非難する）
- ファイア、サンダー（奇跡）
- 雑貨（地方遊説、支持者集会 など）※既存の雑貨カテゴリで掲載済み
- 取引（買う、売る、両替）※既存カテゴリ
- 政党カード ※既存カテゴリ

政党は以前は所属表示のみだったが、現在は守護神と同様のターン終了時効果を持つ
（実装: `packages/game-core/src/parties.ts`、所属表示: `apps/web/src/app/room/[roomId]/NameList.tsx`）。
終了したプレイヤー以外の生存している政党所属者がそれぞれ25%で行動し、
政党ごとの重み付き抽選で以下のいずれかを実行する。

| 政党 | 政党行動 (重み) |
| --- | --- |
| 共産党 | 労働者の反撃: ランダムな生存相手に3ダメージ (60) / 団結: 自分MP+2 (40) |
| 自民党 | 経済成長: 自分お金+3 (60) / 市場の一撃: ランダムな生存相手に2ダメージ (40) |
| 民主党 | 世論の追い風: 自分MP+2 (50) / 政策協力: 自分HP+2 (50) |
| 立憲帝政党 | 王権の威光: ランダムな生存相手に3ダメージ (50) / 城塞の守り: 自分HP+3 (50) |
| 緑の党 | 自然の恵み: 自分HP+3 (60) / 再生エネルギー: 自分MP+2 (40) |
| 無政府党 | 直接行動: ランダムな生存相手に2ダメージ (55) / 略奪: お金を持つ生存相手から2円奪う (45) |

- 解決は `endTurn` 内で、次プレイヤー決定後かつ未勝利のときのみ行う
- HP回復に上限はなく、MP回復は `maxMp` で上限処理する
- 略奪は所持金のある生存相手がいない場合、その行動は何も起こらない
- 政党行動で新たな手番プレイヤーが倒れた場合、勝利していなければ次の生存者へ手番を移す

#### 終末の時と悪魔（実装済み）

以前の教典にあった汎用悪魔（ベリアル、アスタロト、リヴァイアサン）は、
終末の時に出現する政治悪魔へ置き換えた（実装: `packages/game-core/src/devils.ts`）。
終末の時が有効な間、手札を補充するために1枚引くたびに25%で悪魔が出現し、
重み付き抽選（合計25）で1体を選んで手番プレイヤーに効果を与える。

| 悪魔 | 行動 | 効果 (重み) |
| --- | --- | --- |
| 🇺🇸 トランプ大統領 | ツイート砲 | 10ダメージ (7) |
| 🐻 プーチン大統領 | 特別軍事作戦 | 20ダメージ (5) |
| 🚀 金正恩委員長 | ミサイル発射 | 30ダメージ (3) |
| 🐦 イーロン・マスク | アカウント凍結 | 神器を2枚捨てる (5) |
| 🏦 日銀総裁 | 金融緩和 | HP+10 (5) |

- 出現判定と抽選は `endTurn` の rng を共有し、テストでは決定的に再現できる
- 悪魔の効果は手番プレイヤーのみに作用する
- HP回復に上限はなく、金融緩和でHP20を超えることがある
- 手札が2枚未満でもアカウント凍結は残り枚数だけ捨てて処理を継続する

## 決定事項 / 対応方針

- **HPに上限は設けない。** 回復は最大HPを超えてよく、HP20を超える表示は正常。
- **1ターンに複数枚プレイできる**（README のルールを正とする）。修行モードもこのルールに統一する。
- **デッキは全99枚の中から30枚**を選んで構成する。時刻依存の連続切り出しは廃止する（別エージェントが実装）。
- **教典の同期を優先する。** 属性・災いなど未実装のシステムは今回は実装しない。教典には注意書きを掲示し、構想コンテンツは残す。政党効果は守護神相当、悪魔は終末の時の政治悪魔として実装済み。
- **ロビーに名前入力欄を追加する**（別エージェントが実装）。
- **再接続対応は後続ウェーブに回す。** 今回は着手しない。

## 推奨する対応順

1. クライアント状態の不整合を修正する（最優先）
2. 山札を「全99枚から30枚」に変更する
3. ターンルールを複数枚プレイに統一する（修行モードの自動終了を廃止）
4. 教典を実装状況に合わせて更新する（今回は注意書きと不足カテゴリの追記まで）
5. 未実装システム（属性・災い・超常現象など）の実装可否を決める
6. リロード・再接続時の復帰処理を追加する（後続ウェーブ）
